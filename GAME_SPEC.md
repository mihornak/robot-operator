# ROBOT OPERATOR — Game Spec (probe v2, 2026-07-31)

Authoritative spec. Rationale/history: `CONCEPT.md`. Moment-by-moment feel of the teaser: `FIRST_MINUTES.md` (wins on feel). This file wins on systems.

**One-liner:** The central computer is down. You're the operator in the basement, watching security cameras, talking a lone service robot up 15 floors of a malfunctioning facility to turn the computer off and on again.

**Probe scope (locked):** a polished **5-floor authored teaser** ending on a cliffhanger. Pure permadeath. The full game (later, only if the teaser survives its kill criteria) restarts runs into an **autogenerated** climb from floor 1 — the authored tutorial floors never repeat.

---

## 1. Pillars

1. **The relationship is the game** — the negotiation between operator and machine.
2. **Legible comedy** — misunderstanding, refusal, improvisation always OUT LOUD; ambiguity is a joke, illegibility is a bug.
3. **Realtime RTS feel** — talk any time, sub-second acknowledgment, the world never pauses.
4. **There is never a menu** — no clickable UI exists. Space to talk is the entire input surface (plus text fallback).

## 2. Story & presentation frame

- **Fiction:** operator in the underground; one surviving service robot; sticky note on the monitor: *"IF BROKEN: turn the main computer OFF and ON. It's on floor 15. — M."* The quest is an IT-support joke played straight.
- **View:** one security camera per floor, top-down (Archero-like), fixed. Floor transitions = camera-feed cuts with a static burst.
- **The zigzag:** both elevators are broken so each ride goes ONE floor up; the robot must cross the floor to the other shaft. Every floor = elevator A → situation → elevator B. This is the room grammar, diegetically justified. (Linear tower — the route-choice layer from v1 is deliberately dropped for the probe; may return later as stairs/vent forks.)
- **Look:** pixel art (locked), chunky low-res sprites under a CRT post-process (scanlines, jitter, roll, vignette, slight barrel). Near-monochrome dark world — NOT green-phosphor, not horror — with amber OSD text; **the robot is the only saturated thing on screen**. CRT reacts to game state (jitter near danger, glitch frame on damage).
- **UI:** camera-feed OSD only — `CAM 03 · FLOOR 03 · REC ●` + module glyph strip. Zero chrome, nothing clickable.
- **Robot:** R2D2 silhouette — wheels, no legs, swiveling head (head-turn toward camera = the "I heard you" tell). Personality: overconfident toddler. Speech = toddler-speak bible in `FIRST_MINUTES.md` ("ROBOT…", ≤7 words, "WALL IS RUDE"). Funny locomotion animations post-MVP.

## 3. Core loop (teaser)

```
PRESS SPACE → CRT boots (this is the title screen) → robot wakes, asks for orders
→ floor n: cross from elevator A to B through the situation, talking the robot through it
→ powerup ceremonies on floors 2/3/5 → floor 5 → dead camera cliffhanger → title card
DEATH → death card (what it HEARD, what it did, last words) → one key → restart < 2s
```

Teaser target length: ~7 minutes first play. Full-game loop (post-probe): autogenerated floors 1→15, boss floors, run-based roguelike.

## 4. Upgrade axes & the comprehension ladder (progression spine)

The robot is an attribute sheet; every axis is upgradeable, speakable (one word, distinct — naming law), and **funny at the low end** (the low state must generate comedy, not just friction):

| Axis (spoken) | Governs | Low-end comedy | High-end payoff |
|---|---|---|---|
| **EARS** | language comprehension — the ladder below | "ROBOT HEARD MAYBE-LEFT." | rich phrasing, eventually policies |
| **MEMORY** | retention — name → orders persist across floors → conditionals (tier-3 prereq) → policies (tier-4 prereq) → past deaths/grudges (full game) | forgets his own name per floor | the emotional axis; grudge memory endgame |
| **BRAIN** | execution intelligence — straight-line → wall pathfinding → hazard avoidance → tactical positioning | walks through fire to reach the target | smug shortcuts ("ROBOT IS GENIUS.") |
| **EYES** | perception & aim — target acquisition range, accuracy, telling similar objects apart | shoots the mop; "BLOB IS ENEMY?" | spots hidden loot, calls things out |
| **WHEELS** | speed & handling | painfully slow entrances | fast but drifts past doorways |
| **ZAP** | weapon — damage, carry-and-fight capacity | pea-shooter; carrying disables weapon | dual-wield gags |
| **TOUGH** | plating/HP | parts fly off from wall bumps | shrugs off hits, gets cocky |

Personality chips (MAGNET/RAGE/SCARED) are a separate layer — they modify the rule table, not the sheet. Triad design pattern: floor 2 offers *personality*, floor 5 offers *axes* (MEMORY/ZAP/TOUGH). Full game mixes freely.

**The EARS ladder** (comprehension tiers; BRAIN independently governs how well orders are EXECUTED):

| Tier | Name | Understands | Deliberately missing | Teaser |
|---|---|---|---|---|
| 0 | RC Tank | up/down/left/right/stop/shoot | keeps going till told to stop; no targets | start |
| 1 | Fetch | named targets, go-to | wrong-target picks (that's EYES); pathing quality is BRAIN's problem | floor 3 ("NEW EARS") |
| 2 | Phrases | multi-step ("grab the fuse then hide") | steps executed with toddler literalism | full game |
| 3 | Conditionals | one-shot "if X then Y" | needs MEMORY to hold them; interpreted creatively | full game |
| 4 | Policies | standing orders | needs high MEMORY; policies conflict; personality prioritizes | full game endgame |

- **Everything goes through the LLM and the robot (user-locked).** No local command shortcuts in normal play — every utterance is interpreted in context, so "MAGNET", "first card", "the angry one", "I don't care" and "yolo" all work. When the parser is unsure, the robot ASKS AGAIN in character ("ROBOT HEARD MAYBE-LEFT. LEFT?"). The local keyword parser exists ONLY as the zero-keys/offline fail-soft mode. Consequence: the ≤1.5s ack contract rides on the LLM round-trip — model choice must honor it.
- Each tier must ADD comedy, not just remove friction.

## 5. Voice I/O

- **Input:** hold SPACE = push-to-talk (diegetic radio). Web Speech API; feature-detect. Fallback + parallel path: teletype text line on the OSD, same parser. Volume via WebAudio RMS → `shouted` flag (personality reacts).
- **Ack contract:** (1) instant local radio-click + head-swivel on release; (2) ≤1.5s repeat-back in the robot's own words — **raw transcript never shown anywhere** (player can't tell mic error from brain error; protected design); (3) action or loud refusal.
- **Refusals:** deterministic personality triggers + seeded roll, always voiced, cost tempo not runs. Robot refuses HOW, never silently sabotages.
- **Selection UI is voice too:** powerup triads are crates the robot reads aloud ("CRATE SAYS… MAGNET."); the player says ANYTHING — the exact word, "first card", "the angry one", a shrug ("whatever", "yolo") — and the LLM resolves it in context. Stated indifference → the robot CHOOSES, with attitude ("ROBOT PICKS RAGE. ROBOT HAS TASTE."). Unresolvable → robot re-reads the options. **Naming law stays: option names are one word, phonetically distinct** — it keeps the fast path easy, not because matching is exact.
- **TTS (locked):** ALL voice on `eleven_flash_v2_5` — bank AND realtime, NO audio tags ever. Bank ~40 lines (idle barks, wall bumps, acks, refusals, deaths, ceremony lines) pregenerated with the same model; realtime for paraphrased repeat-backs with 15-min session memo. Fail-soft: realtime → bank generic → caption-only. ZERO KEYS = fully playable with captions.

## 6. The robot (probe: exactly one)

- **Brain:** behavior tree ticks every frame; the LLM NEVER acts in the combat loop. Randomness via seeded `mulberry32`. Sim fully deterministic from seed (replayable death cards free).
- **Personality = deterministic rule table** (refuses retreat while a boss is visible unless shouted; sulks 3s when insulted — parser flags insults; prefers shiniest loot). Mood shown as a tiny OSD glyph so obedience is never read as raw RNG.
- **Body = pixel sprite composed of parts** (chassis, wheels, weapon, 2 module slots). Parts visibly break: lost wheel = limping, lost weapon = improvising.
- **Chips (internal archetypes → spoken names):** Hoarder→"MAGNET" (scrap magnet, detours to loot mid-combat), Bloodlust→"RAGE" (+damage, won't disengage), Coward→"SCARED" (+speed, auto-flees at 50% HP). Chips modify stats AND the personality rule table.
- **Name:** the robot has none — it asks the player on first meeting ("ROBOT HAS NO NAME. VOICE GIVES NAME?"), the name is voice-given, stored, and used in barks. Player refuses/silent → "ROBOT NAMES ROBOT: ROBOT."
- **Memory is an upgrade axis (user-locked).** Early memory is BAD: he forgets his own name after a floor ("WHO IS [NAME]? … OH. IS ROBOT."). MEMORY chips/tiers extend retention: his name → orders persisting across floors → conditionals (diegetic prerequisite for ladder tier 3) → standing policies (tier 4) → past deaths/grudges (full game — the phase-2 black-box feature is just the top memory tier). The full progression model: **EARS (understanding) × MEMORY (retention).** Teaser gets: naming beat, the forgetting gag, and MEMORY as a pickable option in the second triad — memory vs firepower is a real voiced choice with a feelable payoff.

## 7. Parser (LLM) contract

- Cheapest fast model that returns reliable constrained JSON sub-second (pick at build: Groq Llama-8B / gpt-5-nano / Gemini flash-lite class). Provider abstracted (Ringmaster `deps.ts` pattern).
- Per utterance: input = utterance + tier + room summary + active choices (triad options, if any) + personality tag → strict JSON `{ intent, target?, condition?, ack_line, insult: bool }`, `intent` tier-gated enum **plus `clarify`** (low confidence → `ack_line` is the in-character ask-again) **and `robot_choice`** (player expressed indifference → robot picks), zod-validated; invalid → one retry → "VOICE IS MUMBLY. AGAIN?"
- **Hard rule:** LLM interprets INPUT only. Never adjudicates outcomes, never touches stats or combat. Deterministic engine executes intents. (Kills the Death by AI / Freysa exploit class; avoids Promptables' "AI decided I lost".)

## 8. The five authored floors (content spec — feel details in FIRST_MINUTES.md)

| Floor | Beat | New | Threat |
|---|---|---|---|
| 1 | zigzag lesson, steering | tier 0, scrap pickup | none (wall bumps are the content) |
| 2 | first triad (MAGNET/RAGE/SCARED) | voice-picked module | sparking floor cable |
| 3 | "NEW EARS" | tier 1 targets | first fused machine: a printer melted onto a vacuum, chasing while spitting crumpled paper |
| 4 | composition, first real danger | — | fused machine + hazard + fragile carryable (fuse; carrying disables weapon) |
| 5 | second triad (incl. MEMORY), victory lap, twist | triad #2: MEMORY / ZAP / TOUGH | light; ends in dead-camera cliffhanger + title card |

**Enemy tone (user-locked): FUSED MACHINES.** The computer being down is WHY the machines went feral — broken office/facility tech merged into creatures: printer-hydra jamming paper, monitor-spider, cable-tangle, a photocopier that copies itself (full-game bestiary). Threatening AND funny; industrial body horror for appliances, never gore.

Boot sequence, death card, idle-bark timings, cliffhanger: scripted in `FIRST_MINUTES.md`.

## 9. Economy (teaser-minimal)

Scrap exists as pickup + death-card stat only. No shop in the teaser (ceremonies replace it). Instructions cooldown-gated by fiction (radio recharge ~2s). No consumable-token metering, no ledgers. Full game: shop every ~3 floors selling parts/chips/controller tiers (tiers are the marquee purchase).

## 10. Tech architecture (locked 2026-07-31 after research — full findings in `TECH_RESEARCH.md`)

- **Rendering: PixiJS v8** (evaluated vs Phaser 4, Godot web, Defold, vanilla, five others — see TECH_RESEARCH.md). Chosen over pure vanilla because the headline visual is stock: `pixi-filters` ships CRTFilter + GlitchFilter + BulgePinchFilter (scanlines, jitter, barrel, vignette, glitch frames as filter params on the root Container). Vanilla-style ownership stands: Pixi renders, WE own the loop and sim. Force `preference:'webgl'` (WebGPU opportunistic, web-only). Hand-roll the chunked tilemap (~150 lines; `@pixi/tilemap` v8-compat unverified). Runner-up on file: Phaser 4 — switch only if the CRT stack disappoints, and verify its post-FX first (LLM corpus is Phaser 3; agents will hallucinate the old API).
- **Client:** Vite + TS + PixiJS, pixel sprites (`scaleMode:'nearest'`, one atlas), fixed-timestep 60fps deterministic sim.
- **Voice is a `CommandSource` interface** — any feature that assumes a mic exists is a bug. Implementations: WebSpeech (prefer Chrome 139+ on-device `processLocally`, quality `'command'`), Typed teletype (fallback + a11y), later: whisper-wasm (lazy-loaded, NEVER in initial bundle — 25–50 MB).
- **Discord is NOT a target platform (user-locked 2026-07-31).** Activities cannot access the microphone at all (iframe lacks the `microphone` permission policy; embedded-app-sdk #363, open, unanswered) — and voice IS the game. Dropped, not deferred. Target platforms: **own-URL web first; web portals (Poki/CrazyGames) later.** Revisit only if Discord ever grants Activities mic permission.
- **The self-contained-bundle law (write into repo CLAUDE.md, commit one):** no runtime CDN, no remote wasm, no dynamic-import-from-URL, `base:'./'` relative paths only. Poki's block-all-external-requests and CrazyGames' relative-paths/≤50 MB-initial rules (and any future embedded context) all demand the same artifact — build to it once, every future port is near-free. Also day one: `-webkit-user-select:none` family + iOS AudioContext resume (CrazyGames requirements).
- **Pixi v8 API rules in repo CLAUDE.md** (`await app.init({...})`, `app.canvas` — never v7's constructor-options/`app.view`): LLMs emit v7 confidently; hard rules stop subagent drift.
- **Server:** one tiny Node/Hono service: `/api/parse` (LLM proxy), `/api/tts` (Eleven proxy + cache), `/api/log` (instrumentation). No rooms/ws/sessions — solo, sim client-side. Copy Ringmaster's env fail-soft patterns; do NOT import its packages.
- **Repo:** this folder, own git repo, pnpm, two packages (`client`, `server`) — the research agent proposed 7; for a 2-week probe the same seams live as FOLDERS inside client (`sim/ render/ voice/ audio/ platform/`) with lint-enforced import rules: `sim/` never imports pixi or DOM; `render/` reads sim state, writes nothing back. Promote folders to packages only if the probe survives.
- Determinism seam kept clean for phase-2 co-op PTT / ghosts (commands = messages).

## 11. Instrumentation & kill criteria (teaser-adapted; committed)

Log via `/api/log`: every command (tier, parse path, intent, complied/refused), floor outcomes, deaths, restarts, completion, death-card share taps.

2-week timebox; playtest ≥8 people, ≥half non-developers, on Discord voice:
- Completion ≥ 60% reach the floor-5 cliffhanger.
- Re-instruct after failure ≥ 35%.
- Laugh-out-loud observed in ≥ half of sessions.
- Zero unprompted death-card/clip shares in week 1 → thesis dead → **kill**.
- (Median-runs criterion deferred to the full game — a teaser isn't a run loop.)

## 12. Build milestones

- **M1 — Silent sim (d1–3):** floors 1–2 playable via teletype text only; BT robot, tier 0 local parser, wall-bump comedy, camera-cut transitions. Funny in text or stop.
- **M2 — Voice loop (d4–6):** space PTT + Web Speech, ack contract, `/api/parse`, repeat-backs, refusals, caption-first.
- **M3 — Comedy & content (d7–10):** floors 3–5, cleaning bot, triads + ceremonies, chips, voice bank recorded, personality table tuned, death card. **The go/no-go gate.**
- **M4 — Teaser hardening (d11–14):** boot sequence, CRT shader polish, cliffhanger + title card, instrumentation complete, deploy, playtests.

## 13. Out of scope (phase-2 list in CONCEPT.md)

Floors 6–15, autogeneration, shop, tiers 2–4, bosses (Magnet Crane parked for full game), multiplayer/shared PTT, ghosts/PvP, black-box grudge memory, roster beyond the one robot, monetization, portals, mobile (desktop browser + mic only). Discord: not out-of-scope but DROPPED as a platform entirely — see §10.
